## Connected learning evidence

- Onboarding → placement → stored estimates/methods → recommended start → daily session →
  lesson responses → mastery/FSRS → future review → dashboard/notebook is covered by service
  integrations and the critical-flow E2E in desktop/mobile. Persistence E2E uses a known wrong
  answer and known right answer, then checks logout, protected-route denial, login, cursor and vocabulary.
- The tutor age/avoir error lowers a previously met writing trace and creates a failed review
  log. Integration verifies that this exact concept/dimension becomes due, generates a review
  exercise and appears in a future daily plan. An unseen contractions concept is deliberately
  not introduced by that conversation. Unmapped/LLM-only corrections stay personal items.
- Speech resolution requires owned recent evidence, successful Azure status, valid actual
  overall score and matching text. Client transcripts/scores are discarded; mismatches,
  expired/mock/invalid evidence and wrong ownership are rejected. Genuine overall changes
  the placement grade. Practice self-rating never becomes objective placement evidence.
- Correctness is available through text, option labels and the live status region, including
  the model answer and correct language. Semantic/browser verification is not a live screen-reader audio test.

## Important findings and fixes

1. Missing application/global error boundaries: localized recovery in the existing design,
   Next 16.4 retry API, independent global layout/font fallback and safe navigation; no raw errors.
2. Reusable/misbound speech evidence and client-only placement scores: bind evidence to the
   authoritative activity, require actual assessment in placement and surface real failures.
3. Unverified signup email could receive admin through ADMIN_EMAILS: remove automatic grants,
   preserve server/database learner defaults, test malicious role/emailVerified input against real auth.
4. Minimal-pair playText exposed the placement answer: private authenticated audio endpoint
   checks owner/current item and persistent quota, synthesizing the keyed word only on the server.
5. Tutor LLM configuration enabled open writing without a grader: exclude unsupported items,
   including resumed plans, and state the limitation honestly.
6. Option labels alone did not announce the right answer: model answers now enter live feedback
   after grading, with PT-BR/French semantics and regression coverage.
7. Practice accepted another learner's session ID: reject before any attempt/memory/review
   write and test that own sessions still work.
8. Production E2E exposed concurrent lesson initialization causing a unique-key error: native
   upsert creates one record and preserves the cursor, tested with ten concurrent starts.
9. E2E_BASE_URL still launched localhost dev, and fast signup hit legitimate production HTTP
   429: external-server mode works; signup honours the retry delay with a bounded retry.
   Production limits remain enabled. The existing ignored B1.1 test was moved unchanged into
   the versioned suite so its ten-lesson coverage survives a fresh checkout.

Earlier committed reliable tutor mapping, locale capabilities, advanced-start fallback and
persistence coverage were retained and verified rather than rewritten.
